# LestingCraft — официальный сайт

Продакшн: **https://lestingcraft.kroterallitir.workers.dev**.

20 маршрутов, адаптивный интерфейс, пять миров с отдельным концепт-артом, журнал с фильтрами, roadmap, FAQ с поиском, инструкции хостинга с копированием, медиа, конфиденциальность и реальные загрузки.

## Устройство

- `public/app.js` — страницы, маршрутизация, поиск, вкладки, клипборд.
- `public/style.css` — responsive layout / reduced-motion / focus states.
- `public/art/` — ИИ-концепт-арт; не игровые скриншоты.
- `public/fonts/` — self-hosted Manrope и Unbounded + OFL лицензии; браузер не обращается к Google Fonts.
- `public/**/index.html` — предварительно отрендеренные страницы для прямых переходов и индексации.
- `template.html` — исходный HTML-каркас.
- `src/worker.mjs`, `src/api.mjs` — API публикаций и статуса backend.
- `server.mjs` — локальный preview-server; привязан к `0.0.0.0`, относительные `/api/...` работают через него.
- `prerender.mjs` — статический HTML всех 20 маршрутов.

Статика обслуживается Workers Static Assets. Только `/api/*` идёт в Worker, без лишних compute-вызовов на каждую картинку. Service binding `COOP` проверяет существующий `lestingcraft-coop` (адрес запроса должен оставаться публичным адресом backend, не выдуманным internal hostname).

## Запуск и проверки (для разработчиков)

```bash
cd Website
npm ci
npm start
# localhost:3900 — для браузера на той же машине; облачный preview проксирует порт.
npm test
npx playwright install --with-deps chromium
npm run test:browser
```

9 сценариев Playwright проходят 20 страниц на desktop/mobile, JS errors, вкладки и клавиатуру, FAQ, фильтры журнала, отсутствие ложных загрузок, реальные ссылки в fixture готового релиза, API error, мобильное меню и clipboard. Сетевые ответы в устойчивых UI-тестах mock'аются. Продакшн API проверяется отдельно — это не выдуманное наличие готового релиза.

```bash
# При работающем npm start, после изменения контента:
npm run prerender
# При необходимости чистого исходного каркаса перед prerender:
# cp template.html public/index.html
```

Prerender не делает 20 одинаковых запросов к публичному GitHub API. В статическом снимке текущая версия не имеет релизов; при загрузке JS браузер обновляет раздел через действующее API. Без JS есть ссылка для ручной проверки GitHub Releases.

## Публикация

```bash
# В окружении, не в файлах проекта:
# CLOUDFLARE_ACCOUNT_ID / CLOUDFLARE_API_TOKEN
npm run deploy
```

Платный тариф не подключается. Статические assets и Worker API остаются в пределах возможностей Workers Free; превышение лимитов может ограничить работу. Свой домен не подключён: используется workers.dev. Service binding должен ссылаться на существующий backend в том же аккаунте.

## Реальные загрузки

Кнопки появляются лишь если релиз:
1. не draft и не prerelease;
2. имеет непустые uploaded assets `build-StandaloneWindows64.zip` **и** `build-WebGL.zip`;
3. ссылки архивов принадлежат именно этому GitHub-репозиторию.

WebGL ZIP подписан как пакет для хостинга, не .exe и не готовая ссылка «играть онлайн». Никаких придуманных требований к ПК, отзывов, числа пользователей или даты выхода.

Публичный GitHub API на shared Cloudflare egress может получать 403 из-за общей rate limit. Тогда API читает `Website/public/releases.json` из публичного raw GitHub; последняя страховка — снимок в assets. `release-feed.yml` в Actions обновляет индекс при публикации/редактировании/удалении релиза и каждые 30 минут, используя штатный `github.token` только в CI. Неизменённый список не создаёт новый коммит. В интерфейсе есть дата снимка. Cache API — до 5 минут. После загрузки assets в существующий релиз возможна задержка до следующей синхронизации.

`npm run test` проверяет фильтрацию готовых и некорректных releases. `node sync-releases.mjs` синхронизирует публичный индекс; `GITHUB_TOKEN` можно передать через окружение. Никогда не коммитить токен или Cloudflare account credentials.

## Безопасность и ограничения

Нет аккаунтов, платежей, рассылки, cookies или клиентской аналитики. Сайт не является игровым backend; код комнаты нельзя публиковать. CSP и прочие защитные заголовки выставлены на продакшне. Локальный preview не ограничивает embedding, чтобы его можно было открыть внутри Arena.

Системные требования игры и полноценный визуальный multiplayer smoke test пока не подтверждены. ИИ-арт — визуальное направление проекта. Репозиторий публичен, но отдельная открытая лицензия проекта пока не объявлена.
