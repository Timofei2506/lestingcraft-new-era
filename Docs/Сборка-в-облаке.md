# Облачная сборка LestingCraft: New Era

## Платформы

| Платформа | Build method | Результат |
|---|---|---|
| Windows x64 | `BuildScript.BuildWindows64` | `build-StandaloneWindows64.zip` |
| Android ARM64 | `BuildScript.BuildAndroidArm64` | `LestingCraft-Android-arm64.apk` |

Веб-сайт показывает прямые ссылки только когда в опубликованном GitHub Release присутствуют **оба** файла. Раздел загрузок — главная страница сайта, `#download` (старый путь `/downloads` перенаправляется туда). Кнопки ведут прямо на файлы релиза.

## Секреты и Unity

Unity Editor и модули устанавливаются на GitHub-hosted runner; на компьютере игрока Unity Hub/Editor не нужны. Версия редактора закреплена в `ProjectSettings/ProjectVersion.txt`. Для CI нужны зашифрованные GitHub Actions secrets `UNITY_USERNAME` и `UNITY_PASSWORD` (Unity ID с Personal-лицензией). Не записывать пароли, PAT, Cloudflare-ключи или keystore в исходники, Resources, логи либо сообщения.

Windows- и Android-задачи выполняются последовательно, чтобы Personal-лицензия не активировалась конкурентно. Вручную: **Actions → Build Windows and Android → Run workflow**. Успешный запуск создаёт артефакты для скачивания в GitHub Actions, но не публикует релиз.

## Windows x64

Скачайте `build-StandaloneWindows64.zip` из артефактов или официального релиза, распакуйте архив целиком и запустите `LestingCraft.exe`. Сохраните рядом папку Data и сопутствующие DLL; не запускайте EXE прямо из ZIP.

Перед публикацией workflow запускает реальную Windows-сборку через Direct3D WARP и проверяет smoke-результат. Публичная публикация также требует набор PNG из исполняемой сборки.

## Android ARM64

Workflow собирает APK с Android ARM64, IL2CPP и временной стандартной debug-подписью Unity; приватный keystore не хранится в CI. APK устанавливается вручную после разрешения установки из источника загрузки. Подпись не гарантирует совместимость обновлений между будущими сборками: если подпись изменится, сначала потребуется удалить старую версию и установить новую заново. Сохраните резервную копию локальных данных игры перед удалением.

На этапе подготовки исходников проверяются проекты и правила содержимого; успешная компиляция APK сама по себе не равна полноценному ручному тестированию на физическом Android-устройстве. Перед массовым распространением следует отдельно проверить установку, запуск, производительность и управление на целевых устройствах.

## Публикация релиза

Workflow `build.yml` запускается вручную либо тегом `v*`. Ручной запуск загружает артефакты и не публикует их. Тег после прохождения обеих платформенных сборок создаёт GitHub Release с Windows ZIP, Android APK и снимками из smoke-сборки. Тег с дефисом публикуется как предварительная версия; сайт показывает её только если оба целевых файла загружены.

Workflow `release-feed.yml` синхронизирует сайт с проверенными asset-ами GitHub Release. API и клиент сайта не формируют ссылку, пока не найдут оба ожидаемых файла; если релиза нет или GitHub временно недоступен, кнопки остаются заблокированными и показывается честное сообщение.
