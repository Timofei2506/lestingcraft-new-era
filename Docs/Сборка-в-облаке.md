# Сборка в облаке — без установки Unity на ПК

Главная идея: **редактор Unity не нужен**. Проект лежит в git, Unity поднимается на
GitHub Actions, лицензия берётся онлайн-входом по Unity ID. Ты скачиваешь готовый билд
или играешь в WebGL по ссылке.

Единственное, что понадобится: **бесплатный аккаунт Unity ID** (регистрация в браузере).

---

## Шаг 1. Два секрета в GitHub (один раз, ~2 минуты, всё в браузере)

1. Репозиторий → **Settings → Secrets and variables → Actions → New repository secret**:

| Имя | Значение |
|---|---|
| `UNITY_USERNAME` | Email от твоего Unity ID |
| `UNITY_PASSWORD` | Пароль от Unity ID |

2. Всё. Никаких `.alf`/`.ulf` файлов больше **не нужно** (см. «Почему не .ulf?» ниже).

> 🔐 Пароль от Unity ID лежит **только** в зашифрованных секретах GitHub и виден только
> экшенам в раннерах GitHub. Никогда не коммить его и не кидай в чат.
> Если на Unity ID включена 2FA — на время сборок её проще отключить (или напиши, разберёмся).

## Шаг 2. Тесты (CI)

Workflow **CI** запускается на каждый push в `main`/`develop` и на pull request'ы:
EditMode-тесты ядра мира (чанки, реестр блоков).

Пока секреты не заданы — CI **пропускает** тесты с заметкой (не падает), чтобы репозиторий не был красным.

## Шаг 3. Билд

Два способа:
- **Actions → Build → Run workflow** — соберёт Windows и WebGL прямо сейчас;
- **Запушить тег** (`git tag v0.1.0 && git push --tags`) — соберёт и автоматически:

| Куда | Что попадёт |
|---|---|
| **Releases** | `build-StandaloneWindows64.zip` (Windows-игра) и `build-WebGL.zip` |
| **GitHub Pages** | WebGL-версия как играбельный сайт |

> Для Pages один раз включи: **Settings → Pages → Source: GitHub Actions**.

## Шаг 4. Играем

- **Windows:** скачай zip из Releases → распакуй → `LestingCraft.exe`.
- **WebGL (слабый ПК):** открой ссылку Pages в браузере — установок ноль.

---

## Почему не старый путь с .ulf?

Unity перевела Personal-лицензии на «named user» (вход по аккаунту):
**ручная активация через `.alf` → `.ulf` теперь доступна только Enterprise/Industry** —
при попытке портал выдаёт «You are not eligible to activate your license offline».
`.ulf`-файлы для Personal Unity 6 вообще больше не выпускаются.

Поэтому CI использует **онлайн-вход по логину/паролю** внутри раннера
(`buildalon/activate-unity-license`): контейнер сам логинится в Unity Licensing,
получает seat на время сборки и возвращает его по завершении. Для твоего ПК — ничего.

## Как это устроено технически

- `buildalon/unity-setup` — ставит Unity Editor **на раннер GitHub** (кэшируется), версию берёт из `ProjectSettings/ProjectVersion.txt`.
- `buildalon/activate-unity-license` — онлайн-активация Personal-лицензии (username/password).
- `buildalon/unity-action` — запускает редактор в batch-режиме: тесты (`-runTests`) и сборка (`-executeMethod BuildScript.*`).
- Оба workflow делят одну concurrency-группу `unity-license`: сборки идут по очереди, чтобы не занимать несколько мест Personal-лицензии.
- Точки сборки — `Assets/Editor/BuildScript.cs` (Windows64 / WebGL, сцены из EditorBuildSettings).

## FAQ

**Мой ПК слабый — потянет?**
Сборка вообще не использует твой ПК. Для игры: WebGL-версия в браузере — самый лёгкий путь;
Windows-билд будет с настройками графики (прорисовка, дальность).

**А если захочу открыть проект в редакторе?**
Не обязательно. Если когда-нибудь захочется — Unity Hub + Unity 6 LTS, открывается как обычный проект.

**Сколько это стоит?**
$0. Personal-лицензия бесплатна (до выручки $200k/год), раннеры GitHub для публичных репозиториев бесплатны.

**CI пишет «Секреты не заданы»?**
Это не ошибка — просто добавь `UNITY_USERNAME`/`UNITY_PASSWORD` (Шаг 1), и тесты/сборки оживут.

**Нужно ли доверять стороннему экшену с паролем?**
`buildalon/*` публичные и используются в продакшене; для максимальной безопасности их можно
запинить на конкретные коммиты (в workflow вместо `@v2` — полный SHA). В форках без секретов
job'ы автоматически пропускаются.
