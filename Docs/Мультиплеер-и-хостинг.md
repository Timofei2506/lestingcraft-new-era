# LestingCraft — кооператив и самостоятельный хостинг

## Статус первого среза

Сервер Cloudflare: **https://lestingcraft-coop.kroterallitir.workers.dev**. Проверка доступности: `/health` (это API, не страница игры).

Реализованы комнаты до **8 игроков**, общий seed и одно выбранное измерение на комнату, позиции/имена игроков, упорядоченные изменения блоков и snapshot при входе. Комната ограничена координатами **−64 ≤ x,z < 64**, высота 256; максимум **4096 различных изменённых ячеек**. Правки существующих ячеек после достижения лимита разрешены.

Сервер — ранний кооперативный прототип, **не** production-сервер выживания. Позиции клиента считаются достоверными. Проверки расстояния до блока, bounds, ID и rate limits не заменяют античит. Пока нет учётных записей, PvP, инвентарей, мобов, авторитетной физики или разграничения прав игроков.

## Как играть без установки Unity

1. Получить WebGL-билд из GitHub Actions / опубликованной страницы игры или Windows-архив. Серверный URL уже задан в `Assets/Resources/NetworkConfig.json`; это публичный адрес, не секрет.
2. В меню указать имя, целочисленный seed и измерение. Нажать **«Создать комнату для друзей»**.
3. Скопировать 32-символьный код комнаты и отправить друзьям приватно.
4. Друзья вводят тот же серверный URL и код, нажимают **«Подключиться по коду»**. Их поля seed/измерение при входе игнорируются: сервер присылает настройки комнаты.
5. После загрузки чанков нажать **«Продолжить»**.

Управление: WASD — ходьба; мышь — обзор; Space — прыжок; Shift — бег; ЛКМ — удалить блок; ПКМ — поставить; 1–9 — материалы; Esc — меню. Блоки можно изменять только в пределах досягаемости. Нижний слой y=0 и установка бедрока защищены.

Каждый, кто знает код, может войти и менять мир. Код — **capability-ссылка**, не пароль и не система ролей. Не публикуйте его. Сохраните код, чтобы вернуться в тот же мир: список комнат в клиенте пока не сохраняется. При разрыве соединения изменения блокируются; выйдите в меню и подключитесь снова, чтобы получить новый snapshot. Автоматический reconnect пока отсутствует.

## Что и где сохраняется

Базовый мир генерируется в клиенте по seed + dimension + generator version. Сервер хранит параметры комнаты и **дельту изменений**, а не миллионы неизменённых блоков.

- **Cloudflare:** SQLite-backed Durable Objects, одна комната — один объект. Изменение блока и номер ревизии записываются в одной транзакции до подтверждения клиентам. WebSocket Hibernation API восстанавливает peer attachments после сна; позиции не пишутся в SQLite на каждый кадр.
- **Standalone Node:** JSON-файл комнаты в `DATA_DIR`, замена через временный файл и rename. Данные загружаются при новом входе после перезапуска. Это простое хранилище прототипа: синхронная запись всего JSON на каждое изменение, не предназначено для большой нагрузки; rename не является гарантией сохранности при отключении питания.
- **Офлайн:** правки живут только в памяти процесса и исчезают при выходе в меню / перезапуске. Дисковое сохранение клиента ещё не реализовано.

R2 в предоставленном аккаунте не включён (API вернул «Please enable R2 through the Cloudflare Dashboard»). **R2 и Neon в этом срезе не используются**. Не требуется подключать платные сервисы. Неизменённые старые ресурсы аккаунта не относятся к игре.

## Бесплатный Cloudflare: ограничения

Конфигурация `Server/wrangler.toml` создаёт SQLite-классы `GameRoom` и `RoomDirectory`, доступные Workers Free. Платный тариф не подключается. При превышении бесплатных квот запросы могут перестать работать до сброса лимита — это не обещание неограниченной бесплатной работы.

Документация Cloudflare: https://developers.cloudflare.com/durable-objects/platform/pricing/ и https://developers.cloudflare.com/durable-objects/best-practices/websockets/ . На дату настройки указаны 100 000 DO requests/day, 13 000 GB-s/day, 100 000 rows written/day; квоты распространяются на аккаунт, а не только на эту игру. Входящие WS-сообщения учитываются по правилам Cloudflare (соотношение 20:1 для requests billing); исходящие не являются отдельными requests. Проверяйте актуальные лимиты в Dashboard.

Наши ограничения: до 32 созданий комнат в день на весь сервер и 4 в час на IP, 15 пакетов/сек на соединение; клиент отправляет позицию максимум 5 раз/сек и только при изменении позиции. Эти лимиты снижают нагрузку, но публичный endpoint всё ещё можно атаковать для исчерпания бесплатных квот. Перед публичным релизом нужны авторизация/Turnstile/дополнительная защита.

## Свой сервер без Cloudflare

Эти команды **для будущего владельца сервера**, не требование ставить что-либо на ПК текущего пользователя.

### Node.js 20+ / 22 LTS

```bash
git clone https://github.com/Timofei2506/lestingcraft-new-era.git
cd lestingcraft-new-era/Server
npm ci --omit=dev
PORT=8787 DATA_DIR=/srv/lestingcraft-data npm start
```

Windows PowerShell:

```powershell
$env:PORT = "8787"
$env:DATA_DIR = "C:\lestingcraft-data"
npm start
```

Открыть HTTP/WebSocket порт 8787 только за reverse proxy. Для WebGL на HTTPS-странице нужен **HTTPS/WSS** endpoint: браузер заблокирует mixed content. Windows-клиент может подключиться к `http://IP:8787` в доверенной локальной сети, но там нет шифрования.

### Docker

```bash
cd Server
docker build -t lestingcraft-server .
docker volume create lestingcraft-worlds
docker run -d --name lestingcraft --restart unless-stopped \
  -p 8787:8787 -v lestingcraft-worlds:/data lestingcraft-server
```

Dockerfile предоставлен как способ упаковки; сам контейнер пока не проверен в этой среде. Проверены Node-сервер и сетевой протокол. Том обязателен для сохранений между заменами контейнера.

### Caddy (TLS + WebSocket proxy)

```caddyfile
play.example.com {
    reverse_proxy 127.0.0.1:8787
}
```

Замените домен, направьте DNS на ваш VPS; Caddy должен иметь доступ к портам 80/443. В клиенте укажите `https://play.example.com`. Для Node лимит создания комнат привязан к непосредственному IP: за reverse proxy это может быть один адрес для всех. Не включайте без проверки доверие к произвольному `X-Forwarded-For`.

### Резервная копия

Остановите standalone-сервер и скопируйте весь `DATA_DIR`. Код комнаты — имя соответствующего JSON-файла. Для восстановления верните файлы и подключитесь по прежнему коду. Автоматического экспорта Cloudflare-комнат пока нет; не удаляйте namespace Durable Objects, если хотите сохранить изменения.

## Развёртывание в другом Cloudflare-аккаунте

```bash
cd Server
npm ci
# Переменные задаются в окружении / CI secret store, не в git:
# CLOUDFLARE_ACCOUNT_ID, CLOUDFLARE_API_TOKEN
npm run deploy
```

Нужны права Workers Scripts Edit и доступ к Durable Objects в своём аккаунте. Рекомендуется отдельный ограниченный токен. Конфигурация не содержит account ID или токенов. Endpoint после deploy задаётся в клиентском меню; чтобы сделать его значением по умолчанию, измените только публичный URL в `NetworkConfig.json` и пересоберите.

## Протокол v1

`POST /api/rooms`: JSON `{ "version":1, "seed":2506, "dimension":0 }` → `{ "type":"created", "code":"...", ... }`.

`GET /api/rooms/{32-hex-code}/ws?name=Alice`: WebSocket.

- Сервер → `welcome`: id, version, seed, dimension, rev, edits[], players[]. Snapshot включает всю ограниченную дельту комнаты.
- Клиент → `position`: x,y,z (позиция камеры), yaw. Сервер → остальным `player` с авторитетным peer id/name.
- Клиент → `edit`: целые x,y,z, block. Сервер → всем `edit` с возрастающей rev **после** сохранения. Клиент не применяет онлайн-правку до подтверждения.
- Сервер → `leave` при отключении, `error` при некорректном пакете.

Seed и версия генератора одинаковы для всех участников. Тесты проверяют согласованность sampler/job; побитовая идентичность всех ландшафтов между Windows и WebGL и двухклиентная Unity-сессия ещё требуют отдельной ручной проверки.

## Проверки

```bash
cd Server
npm ci
npm test
# В отдельном процессе запустить npm start:
npm run test:integration
# Тот же сценарий для Cloudflare:
# TEST_ENDPOINT=https://your-worker.workers.dev npm run test:integration
```

Интеграционный тест проверяет два подключённых клиента, позиции, подтверждение/рассылку изменения, snapshot третьему клиенту, отказ недопустимой правки и уведомление об отключении.

## Безопасность ключей

Cloudflare/Neon/R2/GitHub credentials **не нужны игровому клиенту** и не должны попадать в Unity Resources, WebGL, серверный исходный код или git. Клиенту нужен только публичный URL сервера. Ключи, отправленные в чат, следует отозвать/заменить; новые хранить в secret store, не отправлять в переписку. После текущих операций отозвать ранее переданный GitHub PAT.
